QtBridge Gradle Plugin Configuration Guide

← Back to Main Documentation

Overview

Use the Qt Bridge Gradle plugin to configure and integrate the Qt Bridge environment for Java or Kotlin projects. It ensures that all required Qt and native bridge resources are properly resolved and downloaded if missing.

The Qt Bridge Gradle plugin provides a qtBridge configuration block with three main sections:

Application configuration

The application block defines runtime settings for your Qt Bridge application:

  • name: Specifies a custom name for the Gradle run task. If set to "myApp", you can run your application with ./gradlew myApp. If not specified, the default task name is the project's name.
  • mainClass: The fully qualified name of your main application class (e.g., "com.example.MyQtApplication" if it is in Java and "com.example.MyQtApplicationKt" if it is in Kotlin). This property is required for the plugin to generate a run task.
  • jvmArgs: A list of JVM arguments to pass to the application at runtime, such as memory settings ("-Xmx512m") or system properties.

QML files configuration

The qml block manages QML source files and import paths:

  • entryPoint: Specifies the entry point QML file (e.g., "App.qml"). If not set, the plugin automatically searches for Main.qml or main.qml in your source directories.
  • sourcePath: Defines qml source directory containing the qml entry point. The plugin defaults tosrc/main/qml, but you can specify the designated directory like src/ui/qml. It could be relative or absolute path.
  • importPaths: Specifies for adding additional QML modules (e.g., /workspace/custom/qml). Use this for referencing QML components outside your project structure. They could be relative or absolute path.

Qt Bridge libraries configuration

These optional properties allow manual override of library paths when automatic resolution is not suitable:

  • qtLibraryPath: Specifies the location of Qt framework libraries.
  • qtBridgeLibraryPath: Specifies the location of native Qt Bridge library.

Automatic resolution

The plugin manages the resolution in an automatic manner. Essentially, the plugin enables:

  • The resolution of Qt and QtBridge libraries by downloading missing libraries automatically
  • The search for QML source files in src/main/qml
  • Auto-discovery of the main QML file: Main.qml or main.qml if not explicitly specified
  • Supports additional import paths for additional QML modules

Example usage in build.gradle.kts

// TODO add link to mavenCentral to check the latest version

plugins {
    id("org.qtproject.qt.bridge.qtbridge-plugin") version "0.1.0"
}

qtBridge {
    application {
        name = "myApp"  // optional: creates running task with this name (defaults to project's name)
        mainClass = "com.example.MyQtApplication" // optional: if set, creates run task
        jvmArgs.addAll("-Xmx512m") // additional JVM arguments may be passed like this
    }

    qml {
        entryPoint = "App.qml"  // optional: auto-discovers Main.qml or main.qml if not set
        sourcePath = "src/ui/qml"  // default: "src/main/qml"
        importPaths.from(file("/workspace/custom/qml"))  // optional: for adding additional QML modules
    }

    // optional configuration
    qtLibraryPath = "/path/to/Qt/libs"
    qtBridgeLibraryPath = "/path/to/bridge/native/lib"
}

Note: Run tasks are only created when mainClass is configured.
